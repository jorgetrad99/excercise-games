# ADR-003: `@mediapipe/tasks-vision` as a runtime dependency, with wasm and model vendored

- **Status:** Accepted
- **Date:** 2026-09-16

## Context

PLAN §1.1 picks MediaPipe Pose Landmarker. AGENTS §3 requires an ADR for any runtime dependency and forbids runtime network access for models or wasm.

## Decision

- Add `@mediapipe/tasks-vision` pinned exactly at `1.0.1`.
- `pnpm vendor:models` (`scripts/vendor-models.mjs`) copies `node_modules/@mediapipe/tasks-vision/wasm` → `public/models/wasm/` and downloads `pose_landmarker_full.task` from model version `1` (not `latest`). The download is md5-checked.
- `public/models/` is **gitignored** and regenerated by the script (Jorge, 2026-09-16). The script is the only writer. Agents don't hand-edit anything there.
- A smoke e2e asserts the model and wasm are served locally.

## Consequences

- The repo stays small (~44 MB of binaries kept out of history). A fresh clone needs one fetch at setup time, never at runtime.
- To bump the package or model: change the pin or `MODEL.url`/`md5` in the script, re-run it, and update this ADR.
- `lite`/`heavy` variants (`?model=`) get added to the script when M1 needs them.
